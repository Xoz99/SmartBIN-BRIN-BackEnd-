SmartBIN-BRIN · Arsitektur Sistem

Alur Data Tempat Sampah Pintar Pemilah Otomatis

Dari sensor di lapangan, dua jalur transmisi (LoRa & HTTP untuk perbandingan riset), sampai dasbor pemantauan realtime.

  • Perangkat & sensor
  • Jalur LoRa (923 MHz)
  • Jalur HTTP/HTTPS
  • MQTT (HiveMQ)
  • Gateway
  • Backend
  • Frontend

1 · Arsitektur end-to-end

Alur menyeluruh dari perangkat lapangan hingga antarmuka pengguna.

1

Perangkat lapangan (Edge)

bin-003: STM32 baca sensor → kirim JSON via serial ke Raspberry Pi. Pi menjalankan kamera + model EfficientNet-B3 (TFLite) untuk klasifikasi jenis sampah, lalu memerintahkan STM32 mengaktuasi pemilah. bin-002: ESP32 membaca sensornya sendiri tanpa Raspberry Pi.

2

Transmisi — dua jalur untuk perbandingan riset

Tiap bacaan dikirim lewat LoRa (→ board LoRa32 TX → RF 923 MHz → LoRa Core RX) dan HTTP (langsung ke server). Nilai seq yang sama dipakai di kedua jalur agar packet loss & latensi tiap paket dapat dibandingkan adil. MQTT (HiveMQ) sebagai jalur tambahan.

3

Gateway (Raspberry Pi RX)

gateway_unified.py menerima paket LoRa dari Core RX, menyusun ulang JSON, menandai transport, lalu meneruskan ke backend via POST /ingest/sensor.

4

Backend (VPS smartbin.sbs)

Docker Compose: Caddy (HTTPS otomatis) → Express + Prisma. Data di PostgreSQL, cache di Redis, event realtime lewat WebSocket, layanan predict terpisah. Backend juga berlangganan MQTT dari HiveMQ.

5

Frontend (Vercel · Next.js)

Dasbor status tiap bin, peta lokasi via GPS, monitor kamera dengan overlay deteksi, dan analitik LoRa vs HTTP serta jumlah sampah terpilah — diperbarui realtime lewat WebSocket.

2 · Detail proses Kamera AI (mode PLATFORM)

Siklus deteksi objek di tatakan/buletan pemilah — berjalan di main.py pada Raspberry Pi bin-003. Satu objek diproses satu kali, lalu sistem menunggu aktuator selesai sebelum siap objek berikutnya.

1

Warmup

Kamera dinyalakan lalu dibiarkan settle (auto-exposure) selama CAMERA_WARMUP_SEC. Mencegah frame gelap di awal dikira objek → gerak sendiri.

2

Baseline

Sistem memotret tatakan/buletan dalam kondisi KOSONG sebagai acuan. Area yang dipantau ditentukan ROI_FRAC (fraksi tengah frame = lingkaran pemilah).

3

Deteksi objek

Tiap frame dihitung obj_diff (beda dari baseline) dan move (gerak antar-frame). Objek dianggap ada bila obj_diff > OBJECT_DIFF dan diam (move < STILL_MOVE). Saat kosong, log “menunggu objek” tiap IDLE_LOG_SEC.

4

Konfirmasi diam

Butuh STILL_NEED frame diam berturut sebelum menjepret — menghindari motion blur & deteksi setengah jatuh.

5

Klasifikasi

Frame penuh dijepret → model TFLite EfficientNet-B3 menghasilkan kategori (Organik / Anorganik / B3) + confidence. CONF_THRESHOLD menyaring (0 = semua diproses).

6

Aktuasi

Kategori dikirim ke STM32 untuk menggerakkan pemilah, sekaligus dilaporkan ke backend (tersimpan & muncul di dasbor).

7

Tunggu & re-arm

Kamera nonaktif sementara selama ACTUATOR_SEC_<kategori> + REARM_BUFFER (objek jatuh, pemilah balik). Lalu ambil baseline baru → siap objek berikutnya. Siklus berulang.

Fokus riset: sistem sengaja mengirim data lewat LoRa dan HTTP secara paralel dengan penanda seq & sentAt yang identik, agar dapat dibandingkan dari sisi keandalan (packet loss), latensi, dan throughput — di atas fungsi dasar IoT pemilah sampah otomatis.
